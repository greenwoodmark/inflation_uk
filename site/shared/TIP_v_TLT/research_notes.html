ETF options relative-value model

Phase 1: discrete Q distribution

The option-implied GH distribution is represented on the existing latent normal grid. The existing GH3/GH5 implementation supplies the grid probabilities, GH realization, and forward-centering convention. The adapter in q_distribution.py converts the normalized terminal-price support U = P_T / F into spot-based log returns:

\[ X = \log\left(\frac{F}{S_0}\right) + \log(U) \]

The support is accepted only when every normalized terminal price is positive. The Q forward invariant is:

\[ \begin{aligned} E_Q[U] &= 1 \\ E_Q[e^X] &= \frac{F}{S_0} \end{aligned} \]

Phase 2 decisions

The first physical-view implementation is in physical_views.py.

Point-estimate data

  • Input: an hourly, positive ETF price series or a one-column DataFrame.
  • Timestamps are normalized to a sorted UTC DatetimeIndex, consistent with the ETF storage layer.
  • The estimator uses overlapping hourly one-calendar-month terminal returns:

text X_s = log(P_(s + 1 calendar month) / P_s)

  • The initial endpoint policy is exact: the endpoint must exist at exactly the same UTC hour one calendar month later. Missing endpoints are omitted rather than forward-filled.
  • The estimator is as-of aware: prices at or after the as-of timestamp are excluded.
  • The lookback default is one calendar year, and the horizon default is one calendar month.

Physical statistics

The point estimates are calculated directly from all valid overlapping terminal returns:

  • Scale: interquartile range divided by 1.349.
  • Skew: Tukey medcouple, using statsmodels.stats.stattools.medcouple.

No ordinary third standardized moment is used in this phase.

Dependence-aware uncertainty

Overlapping terminal returns are strongly dependent, so their count is not treated as an independent sample size. The module still reports the diagnostic effective sample size:

n_eff = n / (1 + 2 * sum positive autocorrelations)

The default uncertainty method is now a circular moving-block bootstrap of consecutive observed hourly log returns:

  1. Compute consecutive hourly log returns from the as-of-filtered price path.
  2. Sample circular contiguous blocks, with a default block length of 24 observed hourly returns.
  3. Reconstruct a synthetic log-price path from each sampled hourly-return sequence.
  4. Recalculate the same overlapping one-month terminal-return windows, preserving their observed window lengths and endpoint policy.
  5. Recalculate IQR scale and medcouple skew for each bootstrap path.

The covariance of the bootstrap statistic pairs [IQR scale, medcouple skew] is used directly, without additional ESS inflation because dependence is already represented by the blocks. The result also records marginal standard errors and percentile 95% confidence intervals. The block length is configurable and is capped at the number of available hourly returns.

The former iid terminal-window bootstrap remains available explicitly as bootstrap_method="iid"; only that legacy method applies the n / n_eff covariance inflation. This permits controlled comparison but is no longer the default.

The result records:

  • point targets;
  • covariance, standard errors, and 95% bootstrap confidence intervals;
  • number of overlapping observations;
  • effective sample size and autocorrelation sum;
  • lookback/as-of timestamps;
  • sampling and uncertainty method versions;
  • bootstrap method, block length, seed, and replicate count.

The bootstrap operates on the observed sequence of hourly closes after storage-layer resampling. If the ETF series contains gaps, a block step represents the next observed close rather than an imputed calendar hour; no prices are forward-filled.

Future phases

The next phase will use these physical scale/skew views in a relative-entropy update of the discrete Q distribution. The forward constraint remains hard:

\[ \sum_i p_i U_i = 1 \]

Physical scale and skew will initially be soft, uncertainty-weighted views. The entropy posterior will subsequently be approximated by a GH3 terminal-price distribution.

Phase 3 decisions

Phase 3 is implemented in entropy_update.py as a fixed-support relative-entropy Q-to-P update.

Support and hard constraint

  • The Q support is unchanged: the update changes only node probabilities.
  • U = P_T / F and X = log(P_T / S0) come from the phase-1 DiscreteQDistribution.
  • P must remain absolutely continuous with respect to Q; every Q probability is required to be strictly positive.
  • The posterior satisfies the hard forward constraint:
\[ \sum_i p_i U_i = 1 \]

This is enforced to numerical tolerance and is equivalent to log(E_P[exp(X)]) = log(F/S0).

Entropy parameterization

The posterior is an exponential tilt of Q. Two bounded support features provide scale/skew directions; a scalar forward multiplier is solved by a root finder for every pair of shape multipliers. This keeps optimization low-dimensional while enforcing the forward exactly.

The objective is:

\[ \begin{aligned} D_{\mathrm{KL}}(P\|Q) + \frac{1}{2}\left(\operatorname{statistics}(P)-\operatorname{targets}\right)^\top \operatorname{covariance}^{-1} \left(\operatorname{statistics}(P)-\operatorname{targets}\right) \end{aligned} \]

The physical targets are the phase-2 IQR scale and medcouple skew. They are evaluated as probability-weighted statistics on the fixed support. The phase-2 covariance is regularized only numerically before inversion; the original covariance is retained in the result.

The support-statistics implementation uses weighted empirical quantiles and a probability-weighted medcouple. The latter is a discrete-support extension of the phase-2 statsmodels medcouple and is deliberately exposed for testing.

Diagnostics and failure behavior

The result records posterior probabilities, weighted target statistics, residuals, KL divergence, forward residual, exponential-tilt multipliers, optimizer status, and effective posterior node count (1 / sum(p_i^2)). Non-finite inputs, invalid covariance, non-positive Q probabilities, infeasible forward support, invalid probabilities, or a non-finite optimizer result fail explicitly.

This phase does not yet refit the posterior to GH3 parameters, write GCS data, or add joint TIP/TLT dependence. The entropy result is the discrete P distribution consumed by the next GH3 reprojection phase.

Phase-3 fixed-point test

The entropy tests include a fixed-point case using the same GH3 distribution for Q and for the physical information view:

b = 0.05, g = -0.3, h = 0.25
F = 1.010, S0 = 1.0

Under the current normalized GH convention, the location is derived by centering and the supplied forward. Therefore E[P_T] = 1.010 is checked directly. The phase-2 statistics are calculated from the same Q support and supplied as the P views; the entropy update must return the original Q probabilities, zero KL divergence, and zero forward residual.

For this fixed-point case, the default 4.5-sigma grid is not admissible: these parameters generate a non-positive centered terminal-price node at that truncation. The test therefore uses truncpoint=3.25, the widest tested grid that keeps the normalized terminal-price support positive. This is an intentional log-return-domain validity check, not a parameter change.

Phase 4 decisions

Phase 4 is implemented in gh_projection.py and reprojections the discrete entropy posterior into both GH3 and GH5.

Candidate construction

  • The latent z grid and base normal-grid probabilities come from the original DiscreteQDistribution.
  • Candidate GH3/GH5 raw realizations reuse the existing _model_realisation() implementation.
  • Candidate normalized terminal prices are centered with the base GH quadrature probabilities:

text U_candidate = 1 + raw_candidate - E_base[raw_candidate]

  • Candidates with non-finite or non-positive terminal prices are rejected.
  • The candidate GH distribution therefore preserves the forward exactly:

text E_base[U_candidate] = 1

Reprojection objective

The entropy posterior is the target distribution, with its posterior probabilities used for target weighted quantiles. Candidate GH quantiles use the canonical normal-grid probabilities. The fitting objective is the mean squared normalized error across quantiles from 1% to 99%:

fixed_support_entropy_quantile_l2_v1

This is deliberately separate from the production option-IV fitting objectives.

GH3 versus GH5

Both versions are fitted under the same support, quantile levels, bounds, and objective. GH5 adds the existing c and q deformation parameters. GHProjectionComparison reports GH3 loss, GH5 loss, signed loss difference, loss ratio, and preferred model. A lower GH5 projection loss is evidence that the entropy deformation is not adequately represented by GH3; it is not by itself evidence that GH5 is preferable out of sample.

The output records parameters, quantile residuals, forward error, minimum terminal price, monotonicity violations, boundary hits, optimizer diagnostics, and settings hash. This phase remains research-only and does not alter production option fits or write GCS data.

Phase 5 decisions: TLT rolling research runner

Phase 5 is implemented in tlt_research.py as a research-only, TLT-specific rolling runner. It composes the persisted Q adapter, physical views, entropy update, and GH3/GH5 reprojection for each fit date.

  • The core runner accepts fits and hourly bars in memory; run_tlt_research_from_storage() is a separate local/GCS read wrapper. Phase 5 writes only an optional local CSV artifact and does not schedule jobs or mutate GCS.
  • Fit dates are evaluated with as_of = fit_date + 1 UTC calendar day, so the fit-date session is available while later observations are excluded. Fits are de-duplicated by date, and the latest fit_datetime is retained by the storage loader.
  • Physical views use one year of overlapping hourly one-month returns and the phase-2 IQR scale/medcouple skew diagnostics. The runner defaults to endpoint_policy="next" for irregular ETF sessions; exact endpoints remain available through settings.
  • The realized diagnostic uses the first available hourly observation at or after the one-month target from the selected spot timestamp. It is reported only when future bars exist.
  • Every successful row records physical effective sample size, entropy KL, forward errors, GH3/GH5 quantile projection losses, the preferred projection, Q/P/GH quantiles, and realized terminal-return fields. summarize_tlt_research() reports medians, GH5's lower-loss fraction, forward-error bounds, and empirical quantile coverage.
  • GH5's lower projection loss is interpreted as additional in-sample deformation capacity, not out-of-sample superiority. Overlapping returns are dependent, the ESS-adjusted iid bootstrap is only a first uncertainty diagnostic, and endpoint policy plus dividend/price-adjustment conventions can materially affect results.

Phase 5 block-length selection diagnostic

For the Q1 2025 TLT sensitivity, block length was selected from the dependence of consecutive observed hourly log returns. The selection diagnostic examined both raw returns and absolute returns; absolute returns were used as the volatility-clustering measure. The rule was:

block_length = ceil(1 + 2 * sum positive ACF(abs(hourly_log_returns)))
block_length = clamp(block_length, 6, 120)

For the Q1 sample, raw-return lag-1 ACF was -0.0080, absolute-return lag-1 ACF was 0.0330, positive absolute-return autocorrelation ended by lag 2, and the integrated absolute-return time was 1.089. The rule therefore selected the six-hour floor. This is a research sensitivity rule, not a claim that six hours is a universal optimal block length.

The selected-length Phase 5 run used 400 bootstrap replicates and produced the local artifact artifacts/tlt_phase5_2025Q1_data_driven_6h_400rep.csv. It attempted 60 dates, succeeded on 56, and retained the same four fit/support errors as the shorter sensitivity runs. The median entropy KL was 7.8694, median GH3/GH5 projection losses were 0.11579/0.11554, and GH5 had lower loss on 82.1% of successful dates. The point physical scale/skew targets are unchanged by bootstrap replication count; covariance, confidence intervals, entropy movement, and projection diagnostics are not.

The six-hour 20-replicate and 400-replicate runs differed materially in covariance-driven entropy results, so 400 replicates should be treated as a minimum for this diagnostic and the bootstrap covariance should be checked for stability with additional seeds and replicates before drawing model conclusions.

analogy for this procedure using a biased coin

One thing that worries me about the procedure we have in place for the prior GH3 based on Q-measure to be updated to posterior P-measure is that we are taking out evidence from the past and using this to forecast the future. If the option-implied terminal density is very different from realised over the prior 1-month period, then it could be justified on the grounds that the market environment has changed. In this case, for given uncertainty in the realised returns information update, the greater the distance between prior and information, the more the posterior will move away from the prior, correct?

Yes, broadly that is correct—but with several important qualifications.

Basic logic

At each as-of date, the procedure has:

  1. A current option-implied Q distribution, which is forward-looking.
  2. A physical-information estimate derived from historical returns.
  3. An uncertainty estimate for that physical information.

The entropy update solves approximately:

\[ \min_P D_{\mathrm{KL}}(P\|Q) + \frac12 \left(s(P)-\hat{s}\right)^\top \Sigma^{-1} \left(s(P)-\hat{s}\right), \]

subject to the hard forward constraint.

Here:

  • \(s(P)\) is the posterior scale/skew;
  • \(\hat{s}\) is the historical physical scale/skew estimate;
  • \(\Sigma\) is the uncertainty covariance;
  • \(D_{\mathrm{KL}}(P\|Q)\) penalizes moving away from Q.

Therefore, if the physical information is farther from the Q statistics, then—holding uncertainty fixed—the optimizer generally has to move P further from Q to reduce the view mismatch.

Equivalently, the relevant discrepancy is not simply:

\[ \hat{s}-s(Q), \]

but the uncertainty-adjusted discrepancy:

\[ \left(\hat{s}-s(Q)\right)^\top \Sigma^{-1} \left(\hat{s}-s(Q)\right). \]

This is a Mahalanobis distance.

So:

  • larger discrepancy → stronger pressure to move;
  • greater uncertainty → weaker pressure to move;
  • smaller uncertainty → stronger pressure to move.

Coin analogy

Suppose Q says the coin’s head probability is around \(0.50\), while historical observations suggest \(0.70\).

If the historical estimate is precise:

\[ p_{\text{physical}} = 0.70 \pm 0.02, \]

then P should move substantially above Q.

If the estimate is uncertain:

\[ p_{\text{physical}} = 0.70 \pm 0.20, \]

then P should remain much closer to Q.

Thus, your statement is right:

For a fixed level of uncertainty, a larger difference between the Q-implied statistics and the physical-information statistics creates more pressure for the posterior to move away from Q.

Important qualification: one realized month is not a density

It is worth distinguishing between:

  • comparing the Q density with a physical distribution estimated from many historical observations; and
  • comparing the Q density with one realized monthly return.

A single realized return cannot identify a realized density. It is only one draw from whatever physical distribution prevailed.

The Phase 2 procedure uses overlapping historical one-month returns to estimate scale and skew. That is more informative than one observation, but those returns are highly dependent and may still represent several different regimes.

So the correct statement is:

If the historical physical scale/skew estimates differ materially from the corresponding Q-implied scale/skew, then the entropy update will tend to move P away from Q, subject to the uncertainty and support constraints.

It is not quite:

The last realized month differed from Q, therefore the future distribution should be changed by the same amount.

The regime-change interpretation

Your proposed interpretation is plausible:

The market environment may have changed, so recent realized behavior may be more relevant to the future than the current Q prior.

But the current procedure does not explicitly identify regime changes. It simply treats the historical physical statistics as information about the future.

That creates two possible interpretations:

Regime-change interpretation

The historical sample is revealing a new environment:

  • volatility has risen;
  • skew has changed;
  • tail behavior has shifted;
  • Q has not yet fully adjusted.

In that case, moving from Q toward P may be desirable.

Noise or stale-sample interpretation

The historical difference is temporary or sampling noise:

  • a short-lived shock occurred;
  • overlapping observations exaggerate the effective sample size;
  • the lookback contains mixed regimes;
  • the option market is correctly pricing forward risk that differs from past realized risk.

In that case, moving too far from Q would be harmful.

The entropy framework does not decide between these interpretations automatically. It only provides a controlled way to combine them.

Why the forward constraint matters

The posterior cannot move arbitrarily toward the physical distribution because it must preserve:

\[ \begin{aligned} E_Q[U] &= 1 \\ E_Q[e^X] &= \frac{F}{S_0} \end{aligned} \]0

Therefore, even if the physical scale/skew estimates are far from Q, the update can only modify the probability weights on the existing Q support while retaining the forward.

If the physical target is inconsistent with the available Q support, P will be the closest feasible distribution rather than an exact match.

Why “more distant” does not always mean proportionally more movement

The relationship is generally monotonic in the simple local case, but not necessarily linear or strictly monotonic in every practical run because:

  1. Scale and skew are estimated jointly.
  2. Their covariance matters.
  3. The support is fixed and may limit feasible distributions.
  4. The forward constraint couples all probability changes.
  5. The entropy objective is nonlinear.
  6. Probability weights cannot become negative.
  7. The optimizer may hit multiplier or numerical bounds.
  8. GH3/GH5 reprojection adds a second approximation step.

So greater Q–physical discrepancy creates stronger pressure, but the actual KL movement depends on the geometry of the support and the uncertainty covariance.

The key concern for the current procedure

Your concern is valid: the current update is a form of historical-to-forward extrapolation.

It implicitly assumes that the recent physical return characteristics contain useful information about the next month. That may be reasonable, but it is not guaranteed.

The main risk is:

The entropy update may interpret a temporary past regime as a persistent future regime.

The opposite risk also exists:

The option-implied Q distribution may be slow to reflect a genuine regime change, and the physical update may provide useful early information.

This is exactly why the update should be evaluated out of sample rather than judged only by how well P matches the historical physical views.

What should be added next

The most useful extension would be to make the historical information explicitly regime-aware:

1. Recency weighting

Estimate physical scale/skew using multiple lookbacks:

1 month
3 months
6 months
12 months

Then compare their predictive performance.

2. A dynamic physical/Q blend

Instead of immediately using the full physical update, define:

\[ \begin{aligned} E_Q[U] &= 1 \\ E_Q[e^X] &= \frac{F}{S_0} \end{aligned} \]1

or equivalently damp the entropy tilt:

\[ \begin{aligned} E_Q[U] &= 1 \\ E_Q[e^X] &= \frac{F}{S_0} \end{aligned} \]2

Here:

  • \(\alpha=0\): retain Q;
  • \(\alpha=1\): use the full entropy update;
  • intermediate values: partial adjustment.

3. Predictive calibration

For each date, compare Q, P, GH3, and GH5 against the following one-month return, not the historical data used to form the physical views.

This tells us whether moving away from Q actually improves:

  • quantile coverage;
  • interval width;
  • log score;
  • CRPS;
  • tail calibration.

4. Regime diagnostics

Track whether large Q-to-physical discrepancies occur during:

  • volatility spikes;
  • trend reversals;
  • rate shocks;
  • liquidity events;
  • changes in option skew.

Bottom line

Your reasoning is correct:

For fixed uncertainty, a larger statistically measured difference between Q and the physical information creates greater pressure for P to move away from Q.

But the procedure does not itself prove that the past regime will persist. It is a disciplined way of expressing the hypothesis that it might.

The next important question is therefore not merely:

Did P move away from Q?

but:

When P moved away from Q because recent physical behavior differed, did that improve the distributional forecast of the subsequent month?
